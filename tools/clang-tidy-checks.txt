# The clang-tidy checks tools/lint.sh's `analyze` stage requires to be
# present, one per line.  Compared against `clang-tidy --list-checks` at
# the start of every run of that stage; a check on this list that the
# running binary does not offer is a failure that names it.
#
# Why this file exists.  .clang-tidy at the tree root selects checks by
# wildcard -- bugprone-*, cert-*, clang-analyzer-*, misc-* -- and a
# wildcard resolves to whatever the tool in $PATH happens to implement.
# That makes "the analyze stage passed" a statement about the machine,
# not about the code, in two distinct ways that this file separates:
#
#   1. `clang --analyze` offers NONE of these.  tools/lint.sh degrades to
#      it when clang-tidy is absent and LINT_ALLOW_MISSING=1, and it runs
#      the clang-analyzer engine only -- the whole bugprone-*, cert-* and
#      misc-* families are absent by construction.  Measured, on the
#      canonical probe `long long widen(int a, int b) { return a * b; }`:
#      clang-tidy 18 with this tree's .clang-tidy reports
#      bugprone-implicit-widening-of-multiplication-result; `clang
#      --analyze` on the same file, same target, reports nothing.  That
#      is the class of defect 5 (3UL * sizeof(HANDLE) multiplied in 32
#      bits and widened afterwards, LLP64), and the fallback could never
#      have caught it whatever version was installed.
#   2. Version drift, in the direction that loses checks.  The pinned
#      LLVM 18.1.8 configuration enables 240 checks (2026-09-06: down from
#      260 after .clang-tidy restored its disable list for 20 checks whose
#      entire premise is wrong for this tree -- see that file's own
#      comment); newer releases add
#      checks under these wildcards and can also remove old ones.  A tool
#      offering more is fine and expected.  A tool offering fewer is a
#      silently weaker analysis reporting the same "0 findings".
#
# Generated with the pinned tool, from the tree root so .clang-tidy
# applies:
#
#   nix-shell -p llvmPackages_18.clang-tools \
#     --run 'clang-tidy --list-checks' | sed -n 's/^    //p'
#
# Regenerate it when .clang-tidy's enable/disable lists change, in the
# same commit, and say in the message which checks moved.
#
# Two modes, because the two stages that run this ask different
# questions.  Default: the running tool must offer every REQUIRED check
# below -- a superset is fine and is the intended drift.  With
# LINT_TIDY_EXACT=1: the offered set must equal required + exempt
# exactly.  tools/gate.sh's lint-analyze-pinned stage and ci.yml's
# analyze leg both set it, because their whole purpose is to reproduce
# one exact toolchain, and an exact-equality assertion there is how you
# find out the pin has stopped pinning.  tools/gate.sh's lint-plain
# stage deliberately does not: it runs whatever is installed, and
# demanding LLVM 18.1.8 of it would make it unrunnable on any current
# machine and collapse the distinction between the two stages.
#
# A line beginning with `-` is a check the pinned tool offers that is
# deliberately NOT required of a newer tool.  There are three, all
# removed upstream between LLVM 18.1.8 and 21.1.8, and all excluded for
# ONE reason, stated as a condition rather than a verdict because the
# condition can change:
#
#   THIS TREE COMPILES NO C++ THROUGH CLANG-TIDY.  tools/lint.sh's
#   analyze stage feeds it exactly the source set the Makefile builds --
#   .c files -- so a C++-only check has nothing to fire on and its
#   absence costs nothing.  That is a fact about today's source set, not
#   a property of the checks, and it is asserted mechanically: if the
#   analyze stage is ever handed a .cc/.cpp/.cxx/.C file it fails and
#   says these three exemptions must be re-justified.  (tools/hdr-
#   hygiene.sh has a `cxx` stage that compiles headers as C++, but it
#   uses g++/clang++ directly and never reaches clang-tidy, so it does
#   not invalidate this.)  If C++ ever enters the analyze stage, delete
#   these three lines and deal with the consequences; do not copy them
#   forward.
#
-cert-dcl21-cpp
#   Present in 18.1.8, absent in 21.1.8.  Checks the return type of
#   postfix operator++/--.  C++-only.
-clang-analyzer-cplusplus.VirtualCallModeling
#   Present in 18.1.8, absent in 21.1.8.  Models virtual calls during
#   construction and destruction.  C++-only.
-clang-analyzer-nullability.NullabilityBase
#   Present in 18.1.8, absent in 21.1.8.  An internal base checker,
#   never user-facing.  The user-facing clang-analyzer-nullability.*
#   checks that sit on top of it are still required below, so nothing a
#   C translation unit can trip is lost.
#
# The required list follows.
#
